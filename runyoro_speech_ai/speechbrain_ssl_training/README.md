# Self-Supervised Learning (SSL) Model Training with SpeechBrain

This section outlines the pipeline for SSL pre-training using the SpeechBrain toolkit. Our goal is to adapt a multilingual pre-trained speech model to Runyoro audio.

## Rationale for SpeechBrain

Due to persistent and unusual difficulties in setting up a stable Hugging Face Transformers environment on the target Mac M4 system, SpeechBrain is being adopted as a robust alternative for speech processing tasks.

## Chosen Approach for SSL Model and Base Checkpoint

-   **Base Model Target:** `facebook/wav2vec2-xls-r-300m` (or a similar powerful multilingual SSL model like XLM-R for HuBERT if direct XLSR loading is problematic via SpeechBrain).
-   **Loading Mechanism:** We will attempt to use SpeechBrain's capabilities to load pre-trained weights from Hugging Face models, e.g., via `speechbrain.lobes.models.huggingface_wav2vec.HuggingFaceWav2Vec2` or equivalent components for HuBERT.
-   **Training Goal:** Continued pre-training (domain adaptation) on the Runyoro audio corpus. The specific SSL objective (e.g., masked acoustic prediction, contrastive loss) will be determined by available SpeechBrain recipes and model capabilities.

## Key Dependencies

-   `speechbrain`
-   `torch` (with MPS support for Apple Silicon)
-   `torchaudio`
-   `numpy` (SpeechBrain will specify its compatible version, likely 1.x with current PyTorch)
-   `soundfile`, `pydub` (for audio data handling)
-   Other dependencies will be managed via `pip` and potentially a new `sb_requirements.txt` if needed.

## Data Preparation for SpeechBrain

Before starting SSL pre-training with SpeechBrain, the general audio manifest needs to be converted into a SpeechBrain-compatible JSON format.

1.  **Ensure Base Manifest Exists:** You should have an `audio_manifest.jsonl` file in `runyoro_speech_ai/data/manifest/` (generated by the data ingestion pipeline).
2.  **Run `prepare_sb_ssl_data.py`:**
    This script converts the `.jsonl` manifest into a single JSON file that SpeechBrain recipes typically use.
    From the `runyoro_speech_ai/speechbrain_ssl_training/` directory, you can run:
    ```bash
    python prepare_sb_ssl_data.py \
        --input_manifest_jsonl ../data/manifest/audio_manifest.jsonl \
        --output_sb_json ../data/manifest/sb_ssl_manifest.json
    ```
    Or from the project root:
    ```bash
    python ./speechbrain_ssl_training/prepare_sb_ssl_data.py \
        --input_manifest_jsonl ./data/manifest/audio_manifest.jsonl \
        --output_sb_json ./data/manifest/sb_ssl_manifest.json
    ```
3.  **Output:** This will create `sb_ssl_manifest.json` in `runyoro_speech_ai/data/manifest/`. The `hparams_ssl.yaml` file is configured to look for this file.

## SSL Model Training with SpeechBrain

The SSL training is orchestrated by the `train_sb_ssl.py` script, which uses hyperparameters defined in `hparams_ssl.yaml`.

1.  **Review Hyperparameters:**
    Open `hparams_ssl.yaml` and review settings like `number_of_epochs`, `batch_size`, learning rates, and paths. Ensure `train_sb_manifest_file` points to the correct SpeechBrain JSON manifest (e.g., `../data/manifest/sb_ssl_manifest.json` relative to `data_folder` also defined in the yaml).
    The `wav2vec2_hub` parameter specifies the Hugging Face model to be loaded (e.g., `facebook/wav2vec2-xls-r-300m`).

2.  **Running `train_sb_ssl.py`:**
    From the project root directory (`runyoro_speech_ai/`), execute:
    ```bash
    python ./speechbrain_ssl_training/train_sb_ssl.py \
        --hparams_file ./speechbrain_ssl_training/hparams_ssl.yaml \
        --output_folder ./models/speechbrain_ssl/my_runyoro_sb_ssl_model/ \
        # Optional overrides for hparams defined in train_sb_ssl.py's argparser:
        # --data_folder ./data
        # --number_of_epochs 25 
        # --batch_size 2 
    ```
    -   `output_folder`: Specifies where checkpoints, logs, and other training artifacts will be saved.
    -   The script will automatically try to use MPS on Apple Silicon if SpeechBrain detects it via PyTorch.

3.  **Monitoring Training:**
    -   Logs will be printed to the console (as `train_logger` is set to `stdout` in the YAML).
    -   Checkpoints will be saved in the `output_folder` according to the `checkpointer` settings in the YAML.

4.  **Test Run Script:**
    For a quick test to ensure the pipeline starts and runs for a few steps, you can use the `test_run_sb_ssl.sh` script:
    From the project root:
    ```bash
    bash ./scripts/test_run_sb_ssl.sh
    ```
    This script uses a temporary copy of the hparams file and a dummy manifest to avoid altering your main configuration for a quick test. It also overrides epochs and batch size for a very short run.

**Important Note on SSL Objective:**
The current `train_sb_ssl.py` script contains a **placeholder SSL objective (loss function)**. For meaningful self-supervised learning, this part of the `SSLBrain` class (`compute_objectives` and potentially `compute_forward` for masking/prediction targets) needs to be fully implemented based on a chosen SSL strategy (e.g., Wav2Vec2's contrastive loss, or HuBERT-style masked feature prediction). The current skeleton allows the training loop to run but will not result in a properly pre-trained SSL model without this crucial component.
